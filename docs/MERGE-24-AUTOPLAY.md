# Gameplay autoplay decision

Reviewed 4 November 2026. Retain the accepted poster and explicit Play flow for this release. No autoplay, player SDK, broad media-consent preference or hosted preview video is added.

| Provider | Technical feasibility | Release decision |
| --- | --- | --- |
| YouTube | The documented IFrame API can mute, play, pause and report blocked autoplay. `playsinline` supports inline playback. Browser policy and embedding restrictions can still prevent playback. | Keep click-to-load. A reliable automatic preview would need a provider-specific controller, verified media consent and viewport/preference handling, not just an autoplay query parameter. |
| Vimeo | Documented parameters support muted/autoplay/inline behaviour and an SDK supports pause. Browser autoplay restrictions still apply; Vimeo's `autopause` concerns competing players and is not a viewport observer. | Keep click-to-load; no player connection before the visitor chooses Play. |
| Google Drive | The supported file preview is useful for manual viewing. No supported preview-player API for reliable mute, inline autoplay, blocked-playback detection and pause was established from Google's documentation. Drive file sharing/sign-in also affects availability. | Manual preview only. Do not rely on undocumented query strings, cross-origin DOM access or a file-download proxy. |

Autoplay permission is not privacy consent. The existing optional analytics preference does not authorise media-provider loading, and YouTube privacy-enhanced mode/Vimeo DNT do not eliminate the third-party connection. The existing per-video Play disclosure remains the loading choice. There is no background provider player, preloaded off-screen video, automatic sound or resumed autoplay after consent. Reduced-motion and data-saving users receive the same static poster and manual fallback, so no new automatic motion or media transfer is introduced. Existing poster-image requests remain as documented: first-party screenshot/catalogue images, or a server-fetched public YouTube thumbnail; no direct browser thumbnail-provider request.

A future opt-in preview mode could support YouTube/Vimeo after a separate reviewed media-consent design: default off, explicit provider scope, revocation/expiry, mute before play, user-only unmute, reduced-motion and Save-Data suppression, one visible selected player, viewport and document-visibility pause, blocked-autoplay fallback, strict message origins and SDK cleanup. Consent would permit a request, not guarantee browser playback. This release does not implement or promise that mode. The current manually started cross-origin player does not provide a universal off-screen pause controller; Close player, changing gallery media and navigating away unmount it. No new hosting, transcoding or paid infrastructure is justified for this acceptance release.

Primary references: [YouTube player parameters](https://developers.google.com/youtube/player_parameters), [YouTube IFrame API](https://developers.google.com/youtube/iframe_api_reference), [Vimeo browser autoplay restrictions](https://help.vimeo.com/hc/en-us/articles/29677068222737-Troubleshooting-Autoplay-restrictions), [Vimeo embed options](https://developer.vimeo.com/player/sdk/embed), [Google Drive file reference](https://developers.google.com/workspace/drive/api/reference/rest/v3/files). The Drive conclusion is a limitation of the documented interface found, not a claim that every undocumented workaround fails.
