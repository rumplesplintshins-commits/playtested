# Issue 60: catalogue planning and reception reuse

Base v11 `4a511a8`; no hosted writes or heavy production plans. Production definitions and index metadata were read only. PR 59's speculative-pagination change is excluded.

The platform-filter migration replaced the earlier dynamic/custom-planned catalogue with a SQL-language function. Restoring custom planning alone measured 143.5 → 142.5 ms in the initial empty-link fixture: NO-GO as a material latency fix. A populated 5,000-visible-link stress fixture exposed the correlated profile EXISTS lookup. The new endpoint uses an IN subquery to build the same visible non-null identity set once. RLS still applies under the caller. No filters, ordering expressions, count/window calculation or data rows change. The legacy RPC definition is deliberately left untouched.

Keep the old endpoint and exact row contract; add `get_public_catalogue_page` with six reception display fields as one JSON object per page row. These values already exist in the ranking CTE. The client and homepage seed use the new endpoint, falling back to the old only on missing-function errors. Legacy rows still use the existing reception cache. New rows, including a new-format seed, avoid the separate full reception RPC. Empty pages do not request reception. Permission, query and network errors do not silently fall back. The independent recommendation-intent RPC is retained because its lifetime/build semantics differ from latest-round reception.

Isolated results and outer EXPLAIN ANALYZE/BUFFERS plans are in `issue-60-catalogue.json` (growth stress) and `issue-60-catalogue-current-scale.json`. Read-only production pg_class estimates are 195,362 imports, 9 links, 19 campaigns and 37 feedback rows; listing_controls has zero rows. Production pg_stats description average width is 180 bytes and image URL width 127 bytes. These are metadata estimates, not restored data distributions. Anonymous callers have no visible developer links under current RLS; authenticated owners can see their links. The current-scale fixture reproduces that policy shape and compares both caller results separately. The 5,000-visible-link fixture is explicitly counterfactual for current anonymous traffic; its improvement must not be advertised as a current production latency improvement.

The final sequential current-count/policy-shape run measured 139.67 → 137.43 ms, no material improvement. Earlier current-count runs also showed no meaningful improvement. The growth stress result is recorded separately and cannot support a current latency GO. Nor do the issue's cumulative 860–1,174 ms means establish today's latency.
